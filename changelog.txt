LeftStack Financial Hub: full changelog

= 1.19.0 =
* New: Expenditures, Vendors tab: choose a date range and download the report as a CSV
* New: Privacy tools for donor records. WordPress's Export and Erase Personal Data tools now find contributions by email address. Erasing removes nothing and says the records are kept as campaign financial records. Only administrators can use them. Suggested privacy policy text is added
* Change: The unused fee total stored on each payout is removed from the database. It updates by itself the first time a page loads after the update
* Change: Every file download now goes through one shared routine, tested in a real browser
* Change: Plugin Check reports no findings. Added a contributor setup that works from a fresh clone (seed script, plugin-only wp-env file)

= 1.18.0 =
* New: Expenditures has a Vendors tab. It shows what you spent with each vendor against what was raised, by month and by send, with cost per dollar raised. Vendors can be grouped, and fundraising pages can be grouped with them. Fee expenses are left out of spend
* Change: The ActBlue sync and the donation import fill in a phone number or email that was blank on a donor, never overwriting one you already have, and the result says how many were added. They also say how many payout bank references were filled in

= 1.17.0 =
* New: Local is a fifth election, for PACs and party committees that do not report by election. A Settings switch turns elections off: the election fields and limits are hidden, and new donations and filing periods become Local. Existing records are never changed
* New: Organization types. Choose PAC, party committee, union, business or other on an organization's donation. PACs and party committees are exempt from the organization contribution limit. Donors, the dashboard and refunds carry the type
* New: A warning appears when a donation puts a donor over a contribution limit, both when you enter it and in the ActBlue sync result
* New: Before you file has a Compare with the state section. Save the list the state shows for the period as CSV (or tab separated), choose it, and the Hub shows what is missing, extra or different. It reads the state's own public results export as well as the state's bulk upload format
* New: Before you file shows how many payouts in the period are balanced to the bank, and the State Report window warns while some are not. The payouts table has a Notes column
* Change: Auto-Allocate shows the unitemized total net of refunds
* Change: The state export and the Before you file check now share one rule for which contributions a report holds and when an address is missing. The downloaded files are unchanged
* Change: A filing period whose name and election disagree gets a note. Custom election names are gone: periods use the five listed elections

= 1.16.0 =
* New: The Before you file tab lists the periods that need an amendment. When a donation in a period that was already filed is refunded, the refund is listed under that period until you mark it reported (amend the period on the state site first). "Mark reported" sets the refund's ordinary Filed status; nothing is sent to the state. Refunds with no original donation, or whose original has no filing period, are listed apart
* Change: Filing a payout no longer marks a refund Filed when its original donation is Filed or it has no original, so these refunds stay on the amendments list until you mark them reported. Every other donation in the payout still follows the payout
* Change: Refund cleanup: one rule for what counts as a refund in the donation form and list, the "Donation not found." message is translatable, and an old fix for refunds saved with a positive fee (no longer needed) is removed from the payout sync

= 1.15.0 =
* New: Donations has a "Before you file" tab. Pick a filing period and it lists, by donor and with names, the contributions that would go in the state report and are missing a name, street, city, state or ZIP, and for an individual an occupation or employer. Each contribution has an Edit button that opens the usual form. It only reads: the state export is unchanged
* New: "Best efforts" on that tab records that you asked a donor for their occupation and employer, with the date and a note. One record covers every gift from that donor, and the donor stops being listed for those two items. Remove the record to list them again
* Change: The Donors list and the Dashboard now share one rule for which donations belong to the same donor (no change in what they show)
* Database: adds a table for the best-efforts records (database version 1.21), created automatically

= 1.14.0 =
* New: The donation form has a Filing Period field. It follows the contribution date when you change it, unless you picked a period by hand, and it is locked once the donation is filed. A date outside the chosen period shows a note
* Change: When two filing periods cover the same date, the shortest one is used everywhere: in the forms, when records without a period are placed, and for expenses and in-kind gifts (they used to take the first match)
* Change: A payout is labelled with the filing period most of its donations are in, not the period with the highest ID. The label updates the next time the ledger syncs
* Change: The expense and in-kind forms share one Filing Period field with the donation form

= 1.13.0 =
* New: Find the original gift when you enter a refund. At the top of a new entry, "Refunding a gift? Find the original" searches by donor name, order number (such as AB402867556, or just its digits) or amount, and shows each match with its receipt number. Picking one turns the form into a refund of it, filled the same way as the Refund button on a row. When several gifts look the same (same donor, amount and day), each is flagged so you can tell them apart by the receipt number. A recurring donor reuses one receipt number every month, so one number can list several gifts
* Change: A refund of a gift that did not come through ActBlue now starts with a fee of 0, with a note to match the payout net to your bank. ActBlue returns its fee on a refund, so its refunds still copy the original's fee. Democracy Engine kept the fee, which left one payout off the bank by $2.15
* Change: The donations search, and the exports that use it, also finds a gift by its receipt (order) number
* Change: The fee total on the Disbursements list now comes from the same place as the fee state, so the two cannot disagree

= 1.12.0 =
* New: Each payout now carries the name of who pays it out (ActBlue, OATH, Democracy Engine, WinRed and so on). It shows under the disbursement ID on the Disbursements tab, and you click it to change it. A payout with no name shows "+ add processor" when you point at its row
* New: The Disbursements CSV import asks "Who pays this out?". It is filled in for a file the app recognises when the campaign already has a name for that source, and it is required for a file the app does not recognise. ActBlue files do not ask, because the ActBlue sync names its own payouts
* Change: A payout's fee expense is named from its own processor first, then from the name your other payouts of that source already use, then a default. Payouts that already exist keep their current names until you set one, and a later sync never overwrites a name you set
* Database: adds a processor column to the disbursements table (database version 1.20), upgraded automatically

= 1.11.5 =
* Fix: The Mixed badge on Disbursements no longer flags a deposit just because its date falls in a different period than its donations. It now means the deposit holds donations from a period other than the Filing Period shown on its row
* Fix: A payout date you set by hand now stays. It is copied to the donations in that payout, as the Filing Period already is, so the next sync no longer puts the file's date back. Re-importing the same file still applies the file's date, because re-importing is how you correct data
* Change: Deleting a filing period that records are still filed under asks first and says how many (donations, expenditures, in-kind contributions, deposits). If you go ahead, those records go back to no period and the next ledger sync places them by their dates. Before, the period was deleted and the records kept pointing at it. Deleting a period that does not exist now says so instead of reporting success

= 1.11.4 =
* Fix: The Tennessee export reports a refunded donation at its donation amount. It used to print the amount the donor kept (0.00 for a full refund), but Tennessee wants the contribution as received, with the refund reported separately. A fully or partly refunded donation now exports at its own amount; refunds are still not in the file, and nobody is left out. Re-export a period that included a refunded donation to get the corrected amount

= 1.11.3 =
* New: Fix fees marks a fee expense Balanced when its payout is already Reconciled, which a fee expense never picked up if the payout was reconciled before the expense was linked. A blank Posted date is filled from the payout's Date Received unless that date is in the future. The confirmation shows how many first. A Balanced mark you set by hand is never removed, and a payout that is not reconciled is never touched
* Change: Linking an older fee expense to a payout that is already reconciled also marks it Balanced in the same click
* Change: A fee expense that needs this shows a double check mark on its payout row

= 1.11.2 =
* Fix: On the Bank review the Confirm button now sits in a summary bar under each table (how many are ticked, and the button) instead of against the card edge, and the section headings have their space above them again
* Change: A filing period has to name its election. The New Period form no longer assumes Primary: it follows the name (Pre-General is General) or asks you to choose, and a period with no election is refused
* New: When you add a period or change its election you are asked whether to set the election of the donations dated inside it. The prompt says how many will change, never touches a filed donation, leaves the donations of a shorter period inside it alone, and a payout's election follows when all of its donations agree

= 1.11.1 =
* New: Fix fees also renames a fee expense whose payee is still the payout number (the old fee button named it that way) to the processor that paid the payout, using the name your campaign already uses for that processor's fees (ActBlue, OATH, Democracy Engine). The confirmation shows how many will be renamed first. It never runs on its own, and it only changes a payee that is still the payout number, so a name you typed is kept
* Change: A fee expense that needs this shows a pencil on its payout row, and Fix fees counts it
* Fix: The name for a processor's fee expenses is picked from the most common name in use, counting each fee expense once, so a payout with many donations no longer outvotes the others

= 1.11.0 =
* New: Each payout has one fee expense that stays in step with the fees on its donations. It is created automatically for a new payout, named for the processor (ActBlue, Stripe or Democracy Engine), and its amount changes when a donation or refund in the payout changes. Marking the payout Reconciled balances its fee expense
* New: Fix fees on the Disbursements tab shows what it would create, link or correct (and the total) and asks first. It also links an older fee expense to its payout when the amount matches and the dates are within three days. Payouts from before this version are only changed when you use it
* Change: The fee icon beside a payout fixes a missing or wrong fee expense by changing the one expense, instead of adding an extra adjustment expense
* New: When a payout has more than one fee expense, one click (after a confirmation) keeps the oldest and removes the extras. An older expense that might belong to a payout is flagged for a look instead of being guessed
* New: Expenditures has a Payout column (hide it from the Columns menu) and a fee expense's detail panel shows the payout it belongs to

= 1.10.1 =
* Change: On the Bank page, the list of bank lines that need you is now a To do list. Each card says what is going on and what to do: add the missing record to the Hub, pair some of several deposits of the same amount and add the rest, pair these (with a suggested pairing you confirm with one click), a close amount, or dates that do not fit
* New: Add to Hub on a bank line opens the usual add-expense or add-donation form already filled in from the bank line (date, amount, check number, payment type), so the new record pairs with its bank line at once
* Change: A date you typed from your bank statement (a payout's Date Received, an expense's Posted date, a donation's Date Deposited) is now trusted: it pairs only with the bank line on that date, give or take a day (three for an expense). A typed date that no bank line of that amount fits is flagged for a look instead of being matched or ignored
* Change: A check or cash donation with no Date Deposited yet can match a deposit made any time after it was received, and checks and expenses written up to about three months before the bank file are found by the bank line that cashed them. Older records are never listed as not at the bank
* Fix: Unrelated bank lines that happened to add up to an amount no longer take a record away from the lines of exactly that amount
* Change: The Not at the bank tab explains each record in plain words, including a date that does not match the bank

= 1.10.0 =
* New: Bank page. Add a bank account, upload its CSV (the file is read in your browser and the layout is remembered), and check the control totals against your statement. The review lists suggested matches with the reason for each: clear matches are confirmed together, groups (for example two expenses on one check) are checked one at a time, and anything else is matched by hand with a running difference and a written reason when the amounts differ. A Matched tab lists confirmed matches with Undo, and a Not at the bank tab lists outstanding checks (oldest first) and other records with no bank line
* New: Confirming a match marks what it covers as balanced (a payout is reconciled, which balances its donations) and, with the tick box on, fills blank Date Received, Posted and Date Deposited dates from the bank. A date you typed is never changed, and Undo reverses only what the match set
* New: Disbursements now has a Status column (Filed, Matched, Matched with a difference, Balanced, Synced), a progress line with a Filing period choice and a Needs attention shortcut. Filing a payout that is not matched or balanced asks first, and names any other period it holds donations from. The Unbalanced total under the table now counts every payout, not only the rows on the page
* New: A small bank icon beside the Balanced mark on expenses and donations that are matched to the bank
* New: In the expense form, a check number that other expenses already use shows what the check also covers and what it totals
* Fix: The Tennessee state export no longer stops with an error when a donation has no ZIP code; the ZIP is left blank
* Change: Each screen now loads its own code when its page opens instead of one large file, so pages open a little faster
* Change: Adds four database tables for the bank tie-out (created automatically on update). Bank lines are kept as financial records for audits: the privacy tools list them on request and report them as retained rather than erasing them

= 1.9.110 =
* Fix: organisations whose name contained "PAC" were dropped from the state export. Four organisations worth $3,650 were missing from a filing with nothing on screen saying why. Tennessee loads organisations and PACs on a schedule separate from individuals and removes PACs from the individual upload itself, so they are carried now, and the export reports which ones are in the file
* Add: the export can be limited to individuals only, or to organisations and PACs only — the two sets Tennessee uploads separately. The filename carries the scope, so the two downloads no longer overwrite each other

= 1.9.109 =
* Add: when an imported file reports no payout date, the mapping screen asks for one before importing. Democracy Engine leaves "Transmittal Payment Posted On" empty until a transmittal settles, and the date it settles on may never appear in a file that can be re-imported. Setting it once applies it to the whole file. Leaving it blank is allowed — the payout stays Pending until a date arrives
* Add: a disbursement's date can now be set by hand from the Disbursements table, alongside Date Received and Bank Reference. A date supplied by a file still wins, so this fills a gap the provider left rather than overriding what the provider reports

= 1.9.108 =

Democracy Engine leaves the transmittal's posted date empty until it settles, and MySQL sorts empty dates last on a descending sort, so a payout created by an import appeared not to exist. Payouts still awaiting payment now sort first, and the date column reads "Pending" rather than a dash
* Change: the election is no longer pre-selected when syncing from ActBlue or importing a CSV. Both apply one election to every contribution they create, so neither will run until one is chosen. The split dialog keeps its Primary and General defaults, where the two values are the halves being split
